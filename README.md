# dsh-session-purge

[![npm 最新版本](https://img.shields.io/npm/v/dsh-session-purge.svg)](https://www.npmjs.com/package/dsh-session-purge)

[中文](./README.md) | [English](https://github.com/verdana/dsh-session-purge/blob/main/README.en.md)

给 DeepSeek Harness (DSH) 的会话删除加一个**回收站**：删除不再不可恢复，而是把会话**原样移入
回收站**，可以随时复原、也可以真实删除；回收站不会无限增长——默认保留 30 天，到期自动清理。

上游的「归档」只是把会话从默认列表里藏起来，日志永远留在磁盘上；这个插件管的是**删除**，
而且把「删掉」和「腾出磁盘」拆成了两件事：前者随时可逆，后者交给按时间的自动清理。

> 版本与逐版变更见 [CHANGELOG.md](./CHANGELOG.md)；npm 上的最新版本见上方 badge。

## 功能一览

- **会话行菜单**：`⋯` → **移入回收站**（原来的「删除会话」）。带二次确认，运行中的会话会被拒绝。
- **侧边栏「工作区」行**：搜索 / 视图选项 / 添加工作区 之后的第 4 个图标——**回收站**。
  点开是面板：列出全部已删除会话（标题、原目录、删除时间、大小、会话 id），每条都能
  **复原**或**真实删除**，底部还有**清空回收站**与自动清理策略。
- **也可以放到顶部文字菜单**：设置里的「入口位置」选**菜单**，回收站就变成与
  **插件 / 自动化任务**并列的一行，点开是**整页**（列表更大、行更宽，适合逐条比对）；
  默认仍是图标 + 弹窗。两种形态随时切换，立即生效。
- **账号菜单 → 设置 → 回收站**（0.2.1 起；旧版是侧边栏「设置」按钮）：导航项带垃圾桶图标；
  入口位置、自动清理开关、保留时长（7/30/90/365 天 / 永久）、启动时清理一次、清理周期（1–168 小时）、
  回收站用量统计、**立即清理**、**打开回收站**；页脚显示当前版本并在有新版本时提示。
- **默认策略**：自动清理开、保留 30 天、每次启动 + 每 6 小时各扫一次。改完立即生效，不用重启。

## 安装

```sh
# npm（推荐）
dsh plugin --profile web add dsh-session-purge

# GitHub 仓库
dsh plugin --profile web add github:verdana/dsh-session-purge

# Release 预构建 tarball（免构建授权）
dsh plugin --profile web add <release-tarball-url>
```

装完**重启 `dsh web`**（Host 侧插件只在启动时装载），然后按 Ctrl+Shift+R 刷新页面。

升级与卸载：

```sh
dsh plugin --profile web update dsh-session-purge
dsh plugin --profile web remove dsh-session-purge
```

## 使用

### 把会话移入回收站

鼠标悬停任意会话行 → 点 `⋯` → **移入回收站** → 确认。该行立即从列表消失，
回收站面板里出现这条记录。菜单项、弹窗、面板与设置页都跟随 DSH 的界面语言
（中文界面显示中文，英文界面显示英文）。

### 打开回收站

点侧边栏「工作区」行右侧的**垃圾桶图标**，弹窗列出全部已删除会话，按删除时间倒序：

> 入口位置选了**菜单**的用户没有这个图标：点顶部的**回收站**一行，同样的列表会开在中间栏的
> 整页里（更宽、行信息不挤），底部操作与弹窗完全一致。页面靠点会话或「新会话」返回，
> 和其它全局页面一样没有额外的关闭按钮。

- 每一行：标题（没有标题时显示「未命名会话」）、原工作目录、`删除于 3 天前`、占用大小、会话 id；
  超过保留期的条目会额外标注「将在下次自动清理时删除」。
- **复原**：把会话目录原样移回原来的位置（逐字节还原），侧边栏立即出现该行（无需刷新页面），
  并弹出 toast 报告结果。
- **真实删除**：二次确认后永久删除，不可恢复。
- **清空回收站**：二次确认（会显示条目数与占用体积）后永久删除全部。
- 条目超过 50 条时先显示一页，底部给「加载更多」。
- 条目多到超过一屏时，列表在面板内部滚动，「清空回收站」所在的底栏与策略提示始终留在原位。

### 设置

左下角 **账号菜单 → 设置 → 回收站**（0.2.1 起；更早版本是侧边栏「设置」按钮）：

| 选项 | 默认 | 说明 |
|---|---|---|
| 入口位置 | 图标 | **图标**：工作区行的小图标，点开是弹窗；**菜单**：与「插件 / 自动化任务」并列的一行，点开是整页 |
| 自动清理回收站 | 开 | 关闭后回收站不再自动删除任何条目，只能手动清理 |
| 保留时长 | 30 天 | 7 / 30 / 90 / 365 天或「永久」；超过保留期的条目在下一次清理时被永久删除 |
| 启动时清理一次 | 开 | 每次启动 `dsh web` 时按保留期清理一次 |
| 清理周期 | 6 小时 | 1–168 小时；自动清理关闭时这两项置灰 |
| 立即清理 | — | 立刻按保留期清理一次，并报告删掉了几个条目 |
| 打开回收站 | — | 直接打开回收站面板 |

设置页底部有一条分隔线，下面显示**当前正在运行的插件版本号**。打开页面时还会向 npm 查一次
最新版本：有新版本会给出可点击的提示，已是最新则显示「已是最新版本」；离线、被网络策略阻断或
registry 不可达时静默跳过，只留下版本号，不影响任何设置。版本号由宿主提供，所以升级插件后
需要先重启一次 `dsh web`，只刷新页面还看不到新的页脚。

## 需要知道的

- **删除是可逆的，磁盘不是立刻回收的。** 移入回收站只是把会话目录换个位置；
  真正占用的空间在「真实删除」、清空或自动清理时才释放。
- **运行中的会话移不进去。** 菜单项可以点，但确认按钮会置灰并给出原因（Host 侧还会再校验
  一次）。先停止该会话或等它跑完。
- **恰好开着的空闲会话**：插件会先安全释放它再移动。如果当时无法安全释放（运行时正在收尾等），
  会排进「重启后移入回收站」队列，下次启动 `dsh web` 时执行（想反悔见下面「排查」）。
- **已归档的会话默认不在列表里**，用列表的「视图选项 → 全部对话（显示已归档）」或
  「仅显示已归档」翻出来即可。归档行的菜单是「置顶 / 重命名 / 分叉会话 / 取消归档」，
  **没有「归档会话」这一内置锚点，插件不会在归档行注入「移入回收站」**；需要删除时先
  「取消归档」，再在普通会话行的 `⋯` 菜单里操作。
- **只动能证明身份的目录。** 插件只移动由会话持久层定位到、并且文件名确实是会话日志
  （`session[.vN].jsonl[.zstd]`）的目录；宁可拒绝，也不会动错目录。
- **菜单形态的几处边界**：侧边栏折叠成轨道时那一列只显示图标（上游只在该列展开时渲染文字）；
  菜单行固定是「回收站」，不带条目数（计数仍在图标形态的 tooltip 与页面标题旁）；
  该列里除「插件」外的条目都能被用户收进「更多」菜单，这是 DSH 自己的入口定制，插件同样适用。
  改「入口位置」之前已经在回收站页面里的话，切回图标会退出页面、回到会话。
- **回收站位置**：`~/.dsh/session-purge/trash/`，每条记录是「原会话目录 + 一个同名元数据文件」。
  元数据里记着原始路径、删除时间、大小和归档状态，所以复原是位级还原。
- **设置存在插件自己的文件里**：`~/.dsh/session-purge/settings.json`（原子写入，损坏时自动回退
  默认值并把坏文件留成 `.bak`）。它不走 DSH 的插件配置体系，因此本插件保持零依赖、免构建。

## 排查

- **看不到「移入回收站」菜单项或垃圾桶图标**，先确认插件装上了、`dsh web` 重启过、页面也刷新过
  （Ctrl+Shift+R）。菜单里只要出现「重命名 / 分叉会话 / 归档会话」（0.2.1 起归档后还会多出
  「复制 Session ID」，归档行上是「取消归档」），插件就应该在归档那一项下面插入「移入回收站」；
  图标则紧跟在「添加工作区」之后。
- **找不到设置页**：0.2.1 起设置入口在左下角 **账号菜单 → 设置**，不再有独立的侧边栏「设置」
  按钮；回收站面板底部的策略行也直接提供入口。更早的 DSH 版本仍是侧边栏「设置」按钮。
- **想确认后台到底是什么状态**：

  ```sh
  curl http://127.0.0.1:<端口>/session-purge/state    # 磁盘现状 + 回收站摘要 + 设置
  curl http://127.0.0.1:<端口>/session-purge/trash    # 回收站条目
  curl http://127.0.0.1:<端口>/session-purge/settings # 设置与统计
  ```

  `state` 里的 `sessions[].title` **恒为 null**：会话标题是日志里的**事件**，不在持久层元数据里；
  界面上显示的标题是插件从会话行上读得的，并随移入操作记进回收站条目。
- **还没执行、只是排进「重启后移入回收站」队列的会话**，可以在下次启动 `dsh web` 之前撤下来：

  ```sh
  curl -X POST http://127.0.0.1:<端口>/session-purge/undo \
    -H 'content-type: application/json' -d '{"sessionId":"<会话 id>"}'
  ```

  会话 id 从 `/session-purge/state` 的 `pending` 里取。这个接口只取消排队；已经移入回收站的
  请用面板里的「复原」，已经真实删除的撤不回来。
- **改设置不想开界面**：

  ```sh
  curl -X POST http://127.0.0.1:<端口>/session-purge/settings \
    -H 'content-type: application/json' -d '{"autoClean":false,"retentionDays":90}'
  curl -X POST http://127.0.0.1:<端口>/session-purge/sweep
  ```

- **清空回收站后还剩几条没删掉**：说明宿主拒绝了这几条（最常见的是载荷目录被改成了指向回收站
  之外的链接，安全闸门会拦下）。面板会把这些行留在列表里、在行内标出原因，并提示还剩几个；
  关掉面板重开也还在。确认没问题就先「复原」取回会话，或修好目录再删。

- 详细日志：启动 `dsh web` 时带上 `DSH_PURGE_DEBUG=1`。

## 环境要求

- DSH，`dsh web` 能正常运行。**0.2.1-rc.5、0.2.1-rc.4、0.2.1-rc.2 与 0.2.0-rc.2 上已完整
  实机验证**：回收站面板、设置页的自动清理设置、端到端「移入 → 复原 → 真实删除 → 清扫」，
  以及 0.2.1 的账号菜单设置入口与 0.2.1 插件式 JSONL 后端下的开发脚本。rc.3 没有单独跑过，
  它与相邻两版只差 tooltip 与日志输出层面；rc.2 → rc.5 之间插件依赖的契约面全程未变（详见
  [docs/compat-0.2.1-rc.5.md](https://github.com/verdana/dsh-session-purge/blob/main/docs/compat-0.2.1-rc.5.md)）。
  0.1.7-rc.2 / 0.1.5-rc.3 的菜单与侧边栏注入沿用同一套 DOM 识别，预期可用，但这一轮没有重新
  实机验证；0.1.5-rc.3 没有设置扩展点，**设置页不可用**，此时请用上面的 HTTP 路由读写设置。
- Node.js `^22.19.0 || >=24`（`package.json` 的 `engines`；实际以 `dsh web` 用的
  那份 Node 为准）。
- 零依赖、零编译，Windows / Linux / macOS 同一份代码。
