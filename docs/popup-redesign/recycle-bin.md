# 回收站 · 弹窗与页面视觉重设计

> 状态：已落地到 `client/client.js`。静态预览见 `docs/popup-redesign/recycle-bin-preview.html`。
> 设计技能：`ui-ux-pro-max`（`design_recommend` / `design_search` / `design_review`）。
> 沙箱限制：Playwright 启动 Edge 报 `spawn EPERM`，未生成像素截图；结构由 `tools/bin-ssr-probe.mjs` 与 `tools/client-bin.test.mjs` 验证，预览页由同值 CSS 手写。

## 1. 设计思路

旧面板的根因不是“信息少”，而是**所有信息共用同一种语气**：会话名、`删除于`、`lootboot`、`18.4 MB`、`ID` 都是正文，用户必须逐字读完才知道先看哪。重设计把每个条目拆成四层，按用户扫视顺序排列：

1. **这是什么会话** —— 行标题，14 / 600（页面 15 / 600），primary，单行省略。
2. **它有哪些属性** —— `删除于` / `目录` / `占用` / `ID` 是 10 / 600 的小写 uppercase label，只负责“指路”。
3. **属性值是什么** —— 12 / 500 primary；路径退到 mono 11.5；ID 退到 mono 11 tertiary。
4. **哪条需要现在处理** —— 只有“将在下次自动清理时删除”用琥珀胶囊 + 5px 圆点；永久删除是安静的红字，不抢标题。

视觉语言延续上一轮“移入回收站”弹窗：**Swiss 极简 + 桌面工具**。层级靠字号、字重、颜色和 4/8 间距，不靠给每一行加边框。弹窗是“确认与操作”的短列表，页面是“浏览与定位”的长列表，所以两者共用字阶，但密度不同。

## 2. 信息结构

### 2.1 弹窗（宿主 Modal 路径）

```text
┌──────────────────────────────────────────────────────────┐
│  回收站                                            ✕     │
│  可随时复原；到期后由自动清理永久删除。                  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 会话清理策略                        复原  永久删除 │  │
│  │ 删除于 2 小时前  目录 lootboot  占用 18.4 MB  ID … │  │
│  └────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 另一个会话                          复原  永久删除 │  │
│  │ 删除于 28 天前  目录 dsh-session-purge  占用 24 MB │  │
│  │ ● 将在下次自动清理时删除                           │  │
│  └────────────────────────────────────────────────────┘  │
│  ──────────────────────────────────────────────────────  │
│  共 3 个会话 · 占用 42.8 MB   ● 保留 30 天 ›   清空回收站 │
└──────────────────────────────────────────────────────────┘
```

- 标题只回答“这是什么”，副标题只回答“会怎样”，不重复列表内容。
- 行标题是每一行的第一落点；meta 行是第二落点；操作在右侧垂直居中，不参与文字基线竞争。
- 弹窗 footer 保留统计 + 策略 chip + 清空；页面 footer 只保留“永久删除不可恢复” + 清空，避免和页头的策略 chip 重复。

### 2.2 页面

```text
已删除会话
回收站  [3 个会话]                         占用 42.8 MB  ● 保留 30 天 ›
删除的会话会保留在这里，可在保留期内随时复原。
────────────────────────────────────────────────────────────────────
会话清理策略                                        复原  永久删除
删除于 2 小时前   目录 lootboot   占用 18.4 MB
ID  a1b2c3d4-1111-4a2b-9c3d-0123456789ab
────────────────────────────────────────────────────────────────────
永久删除不可恢复                                     清空回收站
```

页面 head 没有图标：侧栏入口已经有图标，页头再放一个会变成“两个标题”。页面用 overline 建立“已删除会话”的上下文，用 20 / 500 的页面标题与宿主其他页面齐平。

## 3. 文本层级规格

| 层级 | 内容示例 | 字号 / 字重 | 行高 / 字距 | 颜色 | 作用 |
|---|---|---|---|---|---|
| 弹窗标题 | 回收站 | 16px / 600 | 1.3 / -0.01em | label-primary | 第一落点 |
| 弹窗副标题 | 可随时复原；到期后…… | 11.5px / 400 | 1.45 / 0 | 次级文字 | 解释后果 |
| 页面 overline | 已删除会话 | 10.5px / 600 | 1.4 / 0.08em，uppercase | 次级文字 | 建立分区 |
| 页面标题 | 回收站 | 20px / 500 | 28px / -0.01em | label-primary | 与宿主页面齐平 |
| 页面副标题 | 删除的会话会保留在这里…… | 12px / 400 | 1.6 / 0 | 次级文字 | 说明规则 |
| 行标题（弹窗） | 会话清理策略 | 14px / 600 | 1.45 / -0.005em | label-primary | 每行第一落点 |
| 行标题（页面） | 会话清理策略 | 15px / 600 | 22px / 0 | label-primary | 长列表里的锚点 |
| 字段 label | 删除于 / 目录 / 占用 / ID | 10px / 600 | 1.5 / 0.06em，uppercase | 次级文字 | 安静地指路 |
| 字段值 | 2 小时前 / 18.4 MB | 12px / 500 | 1.5 / 0 | label-primary | 答案本身 |
| 路径值 | lootboot | mono 11.5px / 500 | 1.5 / -0.01em，max 34ch | label-primary | 机器数据，等宽易扫 |
| 弹窗短 ID | a1b2c3d4 | mono 11px / 400 | 1.5 / 0 | label-primary | 支持排查，不抢眼 |
| 页面完整 ID | a1b2c3d4-1111-… | mono 11px / 400 | 16px / 0，break-all | label-tertiary | 完整、可复制 |
| 状态胶囊 | ● 将在下次自动清理时删除 | 10.5px / 600 | 1.5 / 0 | label-primary on amber 12% | 唯一琥珀强调 |
| 统计 / footer | 共 3 个会话 · 占用 42.8 MB | 11px / 400 | 1.6 / 0 | 次级文字 | 汇总，不抢行 |
| 策略 chip | ● 保留 30 天 › | 10.5px / 600 | 1 / 0 | label-primary on amber 10% | 可点击的设置入口 |
| 行内操作 | 复原 / 永久删除 | 11.5px / 500 | 1 / 0 | 次级 / error | 安静操作 |
| 页面空态标题 | 回收站是空的 | 13px / 600 | 1.5 / 0 | label-primary | 空态唯一落点 |

**为什么 label 比 value 小？** label 是索引，不是内容。10 / 600 / 0.06em 的 uppercase 在视觉上像一条细线，用户扫一眼就能定位到右侧的值；如果 label 和值一样大，两列会互相打架。

**为什么行标题只比 label 大 4px？** 因为标题的优先级来自 **字重 + primary 色 + 独占一行**，不是来自字号巨大。14 / 600 在 760px 卡片里已经足够重；继续放大反而会让两行条目显得笨重。

## 4. 空间与容器

| 项目 | 弹窗 | 页面 |
|---|---|---|
| 宽度 | 760px；max-height calc(100vh - 48px) | 内容 1040px；左右 padding clamp(24px, 4vw, 48px) |
| 圆角 / 边框 | 16px；1px border-l1 | 无卡片，页面即容器 |
| 阴影 | 0 24px 64px rgba(0,0,0,.30), 0 2px 8px rgba(0,0,0,.12) | 无 |
| Header | 宿主 Modal：22 / 14 / 12 / 24；标题 16 / 600；副标题 11.5 | padding-top 30；eyebrow + title + sub |
| Body | 宿主 Modal：上下 20，左右 24 | 页面自身滚动；head 与列表 gap 18 |
| 行 | padding 12px 12px 11px；圆角 12；行距 8 | padding 14px 16px；圆角 12；行距 8 |
| 行内列 | `minmax(0,1fr) auto`；列距 16 | 同左；列距 20 |
| 字段行 | 字段之间 5px 12px；label 与值 5px | 字段之间 4px 14px |
| Footer | margin-top 12；padding-top 10；上边框 | 同左；只放提示 + 清空 |
| 操作按钮 | 高 30；padding 0 10；圆角 8 | 同左 |

间距只用 4 / 8 的倍数与 10 / 12 / 14 / 18 的视觉修正；没有 13、17 这类碎值。

## 5. 色彩与强调

### 5.1 主题令牌

| 用途 | token | Light | Dark |
|---|---|---|---|
| 卡片 / 页面底 | `--dsw-alias-bg-overlay` | #E9ECF2 | #61666B |
| 主文字 | `--dsw-alias-label-primary` | #0F1115 | #F9FAFB |
| 次级文字基色 | `--dsw-alias-label-secondary` | #61666B | #CFD3D6 |
| 三级文字 | `--dsw-alias-label-tertiary` | #77808F | #AEB6C2 |
| 细边框 | `--dsw-alias-border-l1` | rgba(0,0,0,.04) | rgba(255,255,255,.06) |
| 琥珀强调 | `--dsw-alias-state-warn-primary` | #F59E0B | #F59E0B |
| 错误 | `--dsw-alias-state-error-primary` | #EC1313 | #F25A5A |

### 5.2 次级文字的对比度修正

直接把 `label-secondary` 铺在深色卡片上只有 **3.85:1**，对 10–11.5px 的小字不够。因此容器内定义：

```css
--sd-bin-secondary: color-mix(
  in srgb,
  var(--dsw-alias-label-secondary) 50%,
  var(--dsw-alias-label-primary)
);
```

- Light：#383C40 on #E9ECF2，约 **9.4:1**。
- Dark：#E4E7E9 on #61666B，约 **4.67:1**；在浅色行底上约 **4.54:1**，仍过 4.5:1。
- 主文字：Light **15.97:1** / Dark **5.55:1**。

### 5.3 强调规则

1. **全屏只有一个琥珀语义**：保留期 / 即将到期。它回答“这条还能活多久”，是回收站里最需要确认的信息。
2. **行标题不用颜色强调**，用 14–15 / 600 的字重；避免“到处都是重点”。
3. **路径用等宽字体**，但颜色仍是 primary；它重要在“可核对”，不需要抢眼。
4. **永久删除是安静的红字**：transparent 底，hover 才出现 12% 红底；只有确认条和确认弹窗用实心红。
5. **关闭态降级**：自动清理关闭时，策略 chip 去掉琥珀点、改灰底灰字；信息还在，但不再占用注意力。

## 6. 状态

| 状态 | 表现 | 关键处理 |
|---|---|---|
| 默认 | 正常行 + 琥珀策略 chip | 行标题 primary；label 次级 |
| 即将到期 | 行内琥珀胶囊 + 5px 圆点 | 唯一行内强调；不整行变黄 |
| 自动清理关闭 | muted chip，无圆点 | 不再用琥珀 |
| 空 | 居中标题 + 42ch 说明 | 页面空态占满可视高度 |
| 加载 / 失败 | 居中状态 + 重试链接 | 失败不吞掉 footer |
| 行操作中 | 按钮位置显示“处理中…” | 不改变行高，避免跳动 |
| 永久删除确认 | 红色 tint 确认条 + 实心红确认 | 取消是幽灵按钮 |
| 窄容器（≤780px） | 页面 head 纵向；行单列；操作移到 ID 下方 | 弹窗仍保持双列，标题省略 |

## 7. 交互与无障碍

- 弹窗由宿主 `Modal` 提供 `role="dialog"`、`aria-modal`、Esc、焦点层；标题通过 `aria-label` 暴露。
- 页面是 `role="region"`，用可见标题“回收站”命名；行操作是原生 `button`。
- 策略 chip 是 `button`，`title` 指向设置；不是纯装饰。
- `:focus-visible` 使用 2px 主文字色 outline；不在行内用默认蓝环。
- 琥珀胶囊同时有文字与圆点，不靠颜色单独传达状态。
- 行内操作 30px 高是桌面指针目标；若上触摸设备需放大到 44×44（待补充）。
- `prefers-reduced-motion` 下弹窗入场动画关闭（宿主 Modal 已处理）。

## 10. 待确认 / 待补充

- **品牌色**：当前琥珀来自 DSH `state-warn-primary`，不是品牌色；若有品牌主色，只替换强调色，不要改语义错误色（待补充：品牌 HEX）。
- **深色卡片基色**：当前沿用宿主 `bg-overlay` 的 #61666B 中灰；若设计要“近黑面板”，改 token 后需重验对比度（待补充：目标深色值）。
- **最小窗口宽度**：页面在 780px 容器处切单列；若宿主侧栏可窄于 320px，需要再验标题省略与操作换行（待补充：最小宽度）。
- **触摸目标**：30px 行内按钮适合桌面；触摸端是否统一 44px（待补充：平台）。
- **页面最大宽度**：当前 1040px；若产品希望与设置页 720px 对齐，需要改 `max-width`（待补充：布局规范）。
- **字体**：当前系统栈 + 中文回退；若品牌指定 Plus Jakarta Sans，需要确认中文回退与加载方式（待补充：字体资产）。
